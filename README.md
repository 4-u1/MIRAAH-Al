# مرآة | MIRAAH
### منصة المعاينة الفراغية وجواز الأصل العقاري للتصفية القضائية — نموذج أولي
**Spatial Asset Inspection & Digital Asset Passport for Judicial Liquidation — prototype**

> **مقدَّم لبرنامج "ابتكار إنفاذ" (Infath Innovation)** — جامعة القصيم ومركز الإسناد والتصفية (إنفاذ)، مسار معاينة الأصول.
>
> **تنبيه:** هذا نموذج أولي يعمل **ببيانات توضيحية**. ليس نظاماً رسمياً لإنفاذ أو لأي جهة حكومية، ولا يصدر مستندات أو تقييمات أو شهادات معتمدة.

---

## الفكرة

معاينة الأصول الخاضعة للتصفية القضائية بطيئة، ونتائجها موزعة على تقارير متفرقة، فيتردد المزايدون. "مرآة" تجمع بيانات المعاينة في **جواز أصل رقمي** واحد: ملاحظات العيوب مع أدلتها، ونسبة تغطية الفحص، ومؤشرات محسوبة بمعادلات معلنة، وتصدير موحّد ببصمة SHA-256 تكشف أي تعديل لاحق إذا قورنت ببصمة محفوظة بشكل منفصل.

### 🧪 محاكاة ببيانات توضيحية (Simulated — مُعلَّمة داخل الواجهة)
- كل الأصول والملاحظات والأرقام في `src/data/mockAssets.ts`، والمفتشون أسماء وهمية، والصور توضيحية من مكتبة صور (Unsplash) وليست صور فحص حقيقية.
- مؤشرات صحة الأصل (موجات عشوائية للعرض)، ونسب الثقة في البيانات التوضيحية.
- منظومة PropTech: قراءات IoT، انحرافات BIM/LiDAR، التنبؤ بالدورة الحياتية، سجل بلوكشين، التقييم الآلي AVM، التدقيق القانوني والبلدي.
- مشاهد الطائرة المسيّرة والتوأم ثلاثي الأبعاد: رسم على Canvas ثنائي الأبعاد لبيانات توضيحية.
- مصفوفة SLA ومؤشرات السوق والتوقعات.
- **نماذج المستندات** (صك، تقرير فحص، تقييم، ملخص جاهزية مزاد): نماذج شكلية بعلامة "نموذج توضيحي"، ولم تصدر عن وزارة العدل أو تقييم أو إنفاذ.
- مستكشف الواجهات البرمجية (API Explorer): تصميم مقترح، والنقاط المعروضة غير منفّذة.

## البصمة الرقمية (SHA-256): ماذا تثبت وماذا لا تثبت

- **تثبت:** إذا حُفظت البصمة بشكل منفصل وقت التصدير (مثلاً أُرسلت بالبريد أو سُجلت في محضر)، يمكن لأي شخص إعادة حسابها من ملف JSON واكتشاف أي تعديل لاحق، ولو رقم واحد (`verifyPassportExport`).
- **طريقتها:** SHA-256 على JSON معياري لكائن `passport` (مفاتيح مرتبة تكرارياً بدون مسافات). وقت التصدير `generated_at` خارج البصمة.
- **لا تثبت:** هوية من أصدر الملف، أو صحة البيانات، أو أي اعتماد رسمي. ليست توقيعاً رقمياً ولا تسجيلاً في أي سجل. ومن يعدّل البيانات داخل الملف يستطيع إعادة حساب البصمة المكتوبة فيه، لذلك "فحص ملف JSON" داخل المنصة يكشف فقط عدم التطابق بين البيانات والبصمة المكتوبة في الملف نفسه.
- **ملاحظة تقنية:** الترميز المعياري هنا (مفاتيح مرتبة بدون مسافات) ليس RFC 8785؛ قد يختلف التحقق بلغات أخرى في الأرقام العشرية.

## الأمان

- مفتاح Gemini على الخادم فقط، ولا يصل للمتصفح (يُفحص في CI على ملفات البناء).
- `/api/ai/*`: تسجيل دخول Firebase إلزامي افتراضياً (`AI_REQUIRE_AUTH`)، مع تحقق من التوكن (التوقيع، المُصدر، الجمهور، الصلاحية).
- تحقق من المدخلات بـ zod، وحد للطلب 100KB. حد لحظي لكل IP قبل التحقق من الدخول، ثم حد لحظي وحد يومي **لكل مستخدم** (`AI_BURST_LIMIT`، `AI_DAILY_LIMIT`)، فالطلبات بدون دخول لا تستهلك حصة أحد.
- `TRUST_PROXY`: ‏`loopback` محلياً، و`1` تلقائياً على Cloud Run (عند وجود `K_SERVICE`).
- الخادم يتجاهل ردود "المساعد" المرسلة من المتصفح في سجل المحادثة، فلا يمكن تزوير إجابات سابقة للنموذج.
- بيانات الأصل تُمرَّر للنموذج كبيانات منظّفة داخل `<asset_data>` منفصلة عن التعليمات، وتعليمات النموذج تحصر ما يصفه في الميزات المنفّذة.
- قواعد Firestore: كل مستخدم يصل لملفه وسجلاته فقط، وسجل التحقق إلحاقي لا يُعدَّل ولا يُحذف، بقائمة حقول محددة؛ المعرّف والبريد من توكن الدخول ووقت الإنشاء من الخادم. تُنشر القواعد على قاعدة البيانات المسماة التي يستخدمها التطبيق (`firebase.json`).
- لا توجد ترويسة Content-Security-Policy بعد (مخطط).
- مفتاح Firebase في `firebase-applet-config.json` مفتاح ويب عام بطبيعته؛ يُنصح بتقييده بالنطاق في Google Cloud Console.

## التشغيل

```bash
npm install
cp .env.example .env    # ضع GEMINI_API_KEY إن أردت تفعيل المساعد
npm run dev             # http://localhost:3000
```

| الأمر | الوظيفة |
|---|---|
| `npm run lint` | فحص الأنواع (TypeScript) |
| `npm test` | اختبارات الوحدة والخادم والتعليمات (Vitest + supertest) |
| `npm run test:rules` | اختبارات قواعد Firestore على المحاكي (يتطلب Java) |
| `npm run eval:live` | تقييم سلوك المساعد على نموذج حقيقي (يتطلب `GEMINI_API_KEY`؛ لا يعمل في CI) |
| `npm run build` | بناء الإنتاج (`dist/`) |
| `npm start` | تشغيل نسخة الإنتاج (`NODE_ENV=production`، بيئة Linux) |

متغيرات البيئة موثقة في [`.env.example`](.env.example). يشغّل CI ‏(GitHub Actions) فحص الأنواع والاختبارات والبناء وفحص الأسرار في ملفات البناء واختبارات قواعد Firestore على كل دفع.

## English summary

MIRAAH is a **prototype** built for the Infath Innovation program. It consolidates inspection data for assets in judicial liquidation into a digital asset passport: recorded findings with evidence, inspection coverage, deterministic scores (Condition Index, Coverage, Inspection Confidence, Liquidation Readiness Index), a What-If simulator, and JSON/CSV/PDF exports carrying a real SHA-256 fingerprint of the canonical passport data. An authenticated, rate-limited Gemini assistant answers questions about the displayed data and states plainly what is not available. All data is demo data. IoT, BIM, blockchain, AVM, legal audits, drone views and the specimen documents are simulated and labelled as such in the UI. No integration with Infath, Najiz, Balady, REGA or Taqeem exists yet. This is not an official system and issues no certified documents.
